# 玄界におけるOpenFOAMビルドの調査記録

本ディレクトリは、九州大学「玄界」のセルフホストランナー上でOpenFOAMをビルドするために実施した試行錯誤と、そこから得られた運用上の結論をまとめた記録である。性能比較の多くはv2412で実施し、現行のワークフローはv2512およびv2606を対象としている。本調査が対象とする範囲は**ビルド性能と安定性**のみであり、OpenFOAMのソルバー計算性能、MPI並列実行性能、数値計算結果の妥当性等は扱わない。

本取り組みの目的は、最短時間を記録する単発のベストスコアを出すことではない。再実行性を担保し、失敗時には原因を迅速に追跡可能であり、共有環境の負荷変動を適切に見極められる堅牢なビルドパイプラインを確立・維持することにある。

## 本調査で確立した方針と知見

- OpenFOAMをIntel oneAPIおよびIntel MPI環境下で安定してビルドする手順を確立した。
- ビルドツリーを`/dev/shm`（tmpfs）上に配置し、ソースアーカイブとccacheの永続領域にはランナーの共有ストレージを用いる構成が実用的であると確認した。
- ccacheがウォーム（蓄積済み）状態のときは、ヒット率が約99.5%まで向上する。しかし、`Allwmake`全体の工程には依存関係の生成、リンク、インストール、ファイル走査が含まれるため、コンパイルキャッシュのみで全体のビルド時間をゼロにすることはできない。
- 現在の採用構成は、`Allwmake -j 120`、ジョブキュー制御なし、既定のGNUリンカー（ld）である。
- 同一条件であっても、共有ファイルシステムの混雑状況によって全体の所要時間は約14分台から23分台まで大きく変動する。したがって、単発の経過時間（wall-clock time）のみをビルド最適化の根拠としてはならない。
- ビルド成果物のアーカイブは実行番号（`GITHUB_RUN_ID`）単位で保存し、手動実行またはプッシュ時のコミットメッセージに含まれる`[require-build]`タグによって新規ビルドを制御する。タグがない場合は第一親コミットを遡り、利用可能な過去の成果物を安全に再利用する。

現行構成の詳細は[current-build.md](current-build.md)、試行履歴と判断理由は[trial-record.md](trial-record.md)、性能測定の方針は[measurement-policy.md](measurement-policy.md)を参照のこと。
