# 玄界における OpenFOAM ビルドの調査記録

このディレクトリは、玄界のself-hosted runner上で OpenFOAM をビルドするために行った試行と、そこから得られた運用上の結論を記録したものである。性能比較の多くは v2412 で行い、現在のワークフローは v2512 / v2606 を対象とする。対象は **ビルド性能・安定性** のみであり、OpenFOAM のソルバー性能、MPI 実行性能、数値結果の妥当性は扱わない。

現在の目的は、最短時間の単発記録を作ることではない。再実行可能で、失敗時に原因を追跡でき、共有環境の負荷変動を適切に区別できるビルドパイプラインを維持することである。

## この調査で確立したこと

- OpenFOAM を Intel oneAPI と Intel MPI 環境で安定してビルドできる。
- ビルドツリーは `/dev/shm`（tmpfs）に置き、ソースアーカイブと ccache の永続領域はランナーの共有領域を使う構成が実用的である。
- ccache がウォーム状態のときはヒット率が約 99.5% まで向上する。しかし `Allwmake` 全体は依存関係生成、リンク、インストール、ファイル走査を伴うため、コンパイルキャッシュのみで全体のビルド時間をゼロにすることはできない。
- `Allwmake -j 120`、キュー制御なし、既定の GNU リンカーが現在の採用構成である。
- 同一条件であってもファイルシステムの混雑状況により全体時間は変動する。比較対象となるビルド時間は約14分台から23分台まで観測されており、単発の実時間（wall time）のみを最適化の根拠にしない。
- ビルドアーカイブは実行番号（`GITHUB_RUN_ID`）で保存し、手動入力またはプッシュ時の `[require-build]` で新規ビルドを制御する。それ以外は第一親コミットを遡って利用可能な過去成果物を再利用する。

構成の詳細は [current-build.md](current-build.md)、試行の記録と判断は [trial-record.md](trial-record.md)、今後の測定方法は [measurement-policy.md](measurement-policy.md) を参照する。
