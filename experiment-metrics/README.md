# experiment-metrics v2

OpenFOAMの各種メトリクス記録処理は、診断用のJSONLフラグメント（断片ファイル）を一時ファイルへ書き出し、アトミックなファイル名変更（rename）によって一括して確定します。ジョブスケジューラ上のジョブが完了状態へ移行した後、ログインノード上で動作するGitHub Actionsランナーが各フラグメントを回収し、Google BigQueryへ追記します。値のエンコードにあたって所有者や型の一覧表（レジストリ）は設けず、BigQueryへの書き込みは500行単位のチャンクで実行します。`insertId`の付与や再試行制御は行わず、重複の発生を許容する設計です。なお、BigQueryへの転送失敗は警告（warning）として扱い、ソルバーの実行成否やワークフロー自体の結果判定には影響を与えません。

ワークフローはログインノードからBigQueryへメトリクスを送信するため、パーミッションを`0600`に設定した認証情報ファイルを共有実行ディレクトリ内に一時作成します。機密情報である認証情報を含む環境変数は、環境スナップショットの記録対象から除外されます。この認証情報ファイルは成果物アーカイブには含めず、ワークフローの終了処理において確実に削除（クリーンアップ）します。各記録処理が生成したフラグメントは診断用成果物としてそのまま保持され、中央集約的なマージ処理、単一の`metrics.jsonl`の生成、特定スキーマへの射影、ユーザー向けビューの自動生成、競合解消テーブル、および再送キュー等の複雑な仕組みは設けていません。

ノード数、MPIランク数、処理段階（ステージ）の設定はジョブ実行に不可欠なパラメータであるため、実験条件として独立して管理します。ケースの識別情報、メッシュの来歴、ソルバー名、バージョン、反復回数などの共通項目は各レコードに重複保持せず、固定の課題定義（workload definition）を参照する構造としています。ケースキャッシュの識別ハッシュには、準備スクリプト、公式ケースの内容、検証済みメッシュのSHA-256ハッシュ、領域分割方式、およびランク数を含めて一意性を保証します。
