# experiment-metrics v2

OpenFOAMの各メトリクス記録処理は、診断用のJSONL断片（fragment）を一時ファイルへ書き出し、アトミックなファイル名変更（rename）によって一括で確定します。スケジューラジョブが終了状態になった後、ログインノード上のGitHub Actionsランナーが各断片を回収してBigQueryへ追加します。値の符号化に所有者や型の登録表は使わず、BigQueryへの書き込みは500行ずつのチャンクで行い、`insertId`や再試行は使わずに重複を許容します。転送失敗は警告として扱い、ソルバーやワークフロー自体の結果は変更しません。

ワークフローはログインノードから送信するため、パーミッションを0600にした資格情報ファイルを共有実行ディレクトリ内に作成します。資格情報を含む環境変数は環境スナップショット記録から除外します。この資格情報ファイルはアーティファクトへ含めず、終了処理で確実に削除します。各記録処理が生成した断片は診断用成果物のまま保持し、中央集約的なマージ処理、`metrics.jsonl`の生成、物理形式への投影、利用者向けビューの自動生成、競合表、再送処理などは設けません。

ノード数、ランク数、処理段階（ステージ）の設定はジョブ実行に必要なため、実験条件として独立して管理します。ケース識別情報、メッシュの来歴、ソルバー、バージョン、反復回数を重複して保持せず、固定された課題定義を参照します。ケースキャッシュの識別情報には、準備スクリプト、公式ケースの内容、検証済みメッシュのSHA-256、領域分割方式、ランク数を含めます。
