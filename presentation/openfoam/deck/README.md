# チームのデッキのOpenFOAMパートを作るスクリプト

10/29版のチームのデッキ（130枚）を入力にして、OpenFOAMパートを作り直したpptxを出力します。作り直すのは本編20枚、補足の扉、Q&A目次、補足24枚です。スライドの主張、原稿、根拠の正本は [`../slides.md`](../slides.md) で、このフォルダはそれをpptxにする道具です。

10/31から、`slides.md`は第7版（11/01の時点で本編13枚、約10分、単純で堅い見た目、今の図を流用）に作り直している途中です。このフォルダのコードとこの文書は、まだ第6版（commit `a1f18a3`の`slides.md`、本編20枚）の構成のままです。第7版が決まったら、コードとこの文書を作り直します。

```bash
presentation/openfoam/deck/build.sh [INPUT.pptx] [OUTPUT.pptx] [ASSETDIR]
```

- 入力の既定は `~/apac26/Tokyo Rapids with RIKEN Presentation.pptx`、出力の既定は `~/apac26/Tokyo Rapids with RIKEN Presentation (HPC revised).pptx` です。入力の元はBoxの `Tokyo_Rapids_with_RIKEN_Submission/presentation/` にあります。デッキはリポジトリに入れません。
- `ASSETDIR`（既定は `~/apac26/deck-assets`）には、入力のデッキにも `figures.py` にもない画像を置きます。Boxの `presentation/openfoam/decomposition/` の `decomposition-numa.png`（補足32枚目）と、`panels/` の `multiLevel-car-subdomains.png`、`multiLevel-car-numa.png`（14枚目）です。WSLからはBoxのファイルを読めない（I/Oエラーになる）ので、Windows側でコピーします。
- `build.sh` は、まず `deck_figures.py` で `../figures.py` の図をデッキ用に描き、`deck_plots.py` で各ジョブの点を描く図をスライドの大きさで描きます（下の「作りの決まり」）。次に `build_deck.py` でpptxを作ります。図は一時フォルダに描き、終われば消します。
- OpenFOAMの各スライドは、入力の同じスライドの上で作り直します。だからslide idと、チームが2桁の番号のために広げたスライド番号の欄が残ります。新しく足したスライド（本編7枚目のHOW WE DECIDE WHAT TO KEEP、10/30）だけが新しいslideです。並びは入力と違ってよく、10/30には進め方（OPTIMIZATION STRATEGY）とrooflineを本編から補足へ移しました。
- チームが作った2枚は、Bonusの数値だけを最終版にします（すでに最終版なら何もしません）。補足34枚目のroofline（HPC ROOFLINE: MEMORY AND COMMUNICATION）は5の矢印のラベルの時間を、共通の再現性スライド（47枚目）はOpenFOAMの欄のpatchの並びです。rooflineのノートには、チームのノートの上に補足の形のメモを置きます。区切りの行（「ここまでがデッキのビルド…」）までがビルドの書く部分で、作り直すとそこだけ置き換わります（`team_notes()`）。
- AIパート（入力の47枚目以降、出力の48枚目以降）は1バイトも変えずに残します。

## ファイル

| ファイル | 中身 |
|---|---|
| `build_deck.py` | 各スライドの中身と並び。1つの関数が1枚を作る。入力のOpenFOAMパート46枚の題名が10/29版と違えば止まる |
| `notes.py` | 各スライドのノート。発表者が読む英語の原稿（本編は、その日本語訳も「訳（参考）」として添える）と、チーム向けの日本語のメモ（出典、注意、想定問答）。先頭の[0:35]は話す時間の目安 |
| `decklib.py` | テンプレートに合わせた文字、カード、表、グラフの部品。数字と単位を改行で分けない `tidy()` と、baseline・Basic・Bonusの語に色を付ける `tier_runs()` |
| `palette.py` | スライドと図の色（下の「作りの決まり」） |
| `deck_figures.py` | `../figures.py` をデッキ用に実行する：図の下の注記を描かず、色と数値の書き方をスライドにそろえる。`figures.py` 自体は変えないので、レポートの図はそのまま |
| `deck_plots.py` | 速さを比べる図（各ジョブの点と平均の棒）と、4ノードの道筋の図を、スライドに置く大きさで描く。データと読み込みは `../figures.py` のものを使う |
| `render.ps1` | PowerPointでスライドをPNGに書き出す（Windows、確認用） |
| `qa_grid.py` | 書き出したPNGを並べた一覧画像を作る（確認用） |
| `qa_gaps.py` | 書き出したPNGで、各スライドの内容の下に残った余白を測る（確認用） |

## 作りの決まり

- テンプレートのレイアウト「白背景_タイトルとテキスト_横のコピー」に載せ、タイトルはマスターの32 pt、主張の1行は紺の20 pt（補足は18 pt）、本文はメイリオです。
- 本文は主張の下（1.6 in）から下端の線（7.0 in、スライド番号の上）までを使い、下に帯を残しません。空いたときは、まず図、グラフ、表を大きくし、次に文字を少し大きくし、残りを塊の間隔に配ります。
- スライドの下に、小さな文字の補足（出典、条件、但し書き）を置きません。出典とissue番号（#NN）はノートに書き、スライドには書きません（審査員はリポジトリを見ないため）。図の条件は、図の見出しの下の1行に書きます。補足34枚目のrooflineの最下行の注記はチームの版のままです。
- 図と表には、スライドの順に番号を付けます。本編はFigure 1、Table 1から、補足はFigure S1、Table S1からです。`build_deck.py` の `heading()` と `figure_caption()` が数えるので、スライドを足したり並べ替えたりしても振り直されます。見出しは「Figure 5. 何の図か」の形で、何を比べているかが分かるように書きます。チームのrooflineには番号を振りません。
- 色は `palette.py` にまとめてあります。
  - アクセントは紺（主張の1行、カードの見出し、箇条書きの点、表の見出し）です。
  - baselineは緑、Basicは黄（濃い黄土色）、Bonusは赤です。作業が進むほど暖かい色になります。どれもアクセントの紺と見分けがつきます。
  - 紫は、遅いもの・壊れているものだけに使います（固定が外れたrank、待ち時間、チャネル半分で遅くなる、など）。改善の数字はその段の色（Basicなら黄、Bonusなら赤）で書きます。
  - 文字の色はプロジェクタで薄く見えないよう濃くしています。背景の塗り（カード、表）は薄いままです。
  - 文字を載せる箱（カード、図の中の箱）は、どのスライドでもすべて同じ薄い灰青（`LIGHT`）です（10/30にそろえた）。箱の中の箱は白に罫線、その中はまた`LIGHT`です。違う色にするのは強調だけで、そのスライドの要点（3枚目の「≈ 290 GB/s」、14枚目の「Same computation」）とTAKEAWAYの札は`TINT`、Bonusの結果や部品はBonusの薄赤、段の札と問いの札は塗りつぶしです。表の強調行（補足24枚目の上の3行）も`TINT`です。
  - 1枚に使う色をしぼります。強調したいもの1つに色を付け、ほかは紺と黒（灰）で書きます。
- baseline、Basic、Bonusの語は、本文、表、見出しのどこに出ても、自動でその段の色になります（`tier_runs()`）。凡例を置かなくても色が覚えられるようにするためです。白抜きの文字（表の見出し、札）と、「pre-change baseline」「its own baseline」（パッチを外したBonusのこと）、「the new baseline」、主催者の「common baseline」は色を付けません。
- 数値は `s/step` と書き、%の前に空白を入れません（「21%」）。`tidy()` は「21 %」を「21%」に直します。`figures.py` も同じ書き方で描きます。`deck_figures.py` は、図の負の数をマイナス記号（−）にします（「21 %」「s / step」が紛れ込んでも直します）。
- 速さを比べる図は、棒グラフではなく、各ジョブを点、平均を棒で描きます（`deck_plots.py`）。ノード数ごとの時間、変化、何本で測ったかが1枚で見えるようにするためです。変更ごとの効果（補足39枚目）は、各ジョブを自分の対照の平均に対する%で描き、対照の点の散らばりでその時期のばらつきを見せます。ほかの各runの点を描く図（ばらつき、コンパイラの比較）は `figures.py` の画像、カウンタや割合はPowerPointで編集できるグラフ、表はPowerPointの表で作ります。
- Bonusは、最初の4つの変更（0001〜0004、fa4f5b0、ビット一致）と、後の10個（0006、0008〜0016、うち3つはF3で判定）を分けて書きます。カウンタ、CrayPAT、配置の実験は最初の4つでしか測っていないので、そのことを見出しか行の名前に書きます。
- 分割の絵、流れの動画、メッシュの図は、入力のデッキに入っているものを使います。分割の絵は3列×3段の合成画像から列と段を切り出しています。14枚目と補足32枚目の絵だけは `ASSETDIR` から取ります。
- まとめの札（13枚目）は「TAKEAWAY」、結論の右下は「How we worked」です。「LESSON」という語は使いません。
- 数値は [`../../../submission/openfoam/REPORT.md`](../../../submission/openfoam/REPORT.md) と `../data/*.csv` から取ります。数値を変えるときは、`slides.md`、`notes.py`、`build_deck.py` の3か所をそろえます。桁の決まりは、第6版の `slides.md` では「数値の桁」、第7版では「見た目と言葉の決まり」にあります。

## 確かめ方

1. `build.sh` が `saved ... with 131 slides` と131枚の題名を出して終わること。
2. `render.ps1` で書き出して、全スライドを等倍で見る。見るのは、文字のはみ出し、要素の重なり、数字と単位や「1 v 1」が別の行に分かれていないか、です。PowerPointは255文字を超えるパスを開けないので、`render.ps1` は短いパスにコピーしてから開きます。

    ```bash
    powershell.exe -File "$(wslpath -w presentation/openfoam/deck/render.ps1)" -Pptx "$(wslpath -w "$HOME/apac26/Tokyo Rapids with RIKEN Presentation (HPC revised).pptx")" -OutDir 'C:\Users\<you>\AppData\Local\Temp\deck_png'
    ```

3. `qa_gaps.py` で、各スライドの内容の下の余白を測る。内容のあるスライドは0.45〜0.95 inになります。1 inを超えるスライドは、下に帯が空いています（縦中央にそろえた注記だけの列は除く）。補足34枚目と47枚目はチームの版の配置のままです。

    ```bash
    uv run presentation/openfoam/deck/qa_gaps.py /mnt/c/Users/<you>/AppData/Local/Temp/deck_png
    ```

4. Q&A目次（22枚目）の各行が、その番号のスライドへ飛ぶこと。
5. 入力と出力を比べて、AIパートが1バイトも変わらず、OpenFOAMパートの差が意図した変更だけであること（スライドごとの文字、図形の位置と大きさ、ノートの差分を見る）。

## 注意

- `build_deck.py` は、入力のスライドを位置で使い、素材（動画、メッシュ図、分割の絵、パッチ詳細の2枚、チームの2枚）もそこから拾います。だから入力は10/29版のデッキに限ります。チームがデッキを更新したら、次のどちらかにします。
  - この出力の1〜47枚目を、PowerPointの「スライドの再利用」で更新後のデッキへ移す。
  - 更新後のデッキを入力にするよう、`build_deck.py` の `INPUT_TITLES` と各スライドの位置を書き換える。そのときは、入力の手直し（チームが足したスライド、直した数値や配置）を探し、意図したものか確かめてから取り込む。
- 出力のpptxを手で直したときは、作り直す前に、その変更を `build_deck.py` に入れます。作り直すと上書きされるためです。入れる前に、その変更が意図したものか確かめます（10/21にpptxから消えていた再現性スライドは、誤って消したものでした）。
- PowerPointはen dash（3.19–3.58）の後ろで改行します。改行を避けたい範囲は「3.19 to 3.58」と書きます（`tidy()` が改行しない空白でつなぎます）。
- 改行しない空白でつないだ語が枠より長いと、PowerPointはその語の途中で折ります。表の列は「−12.16%」や「2 nodes」が収まる幅にします。
