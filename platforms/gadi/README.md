# Gadiの運用

Gadiでは、小ファイルを大量に置く処理と、長く保存する大きなファイルを分けます。

- `$PBS_JOBFS`には、ソースの展開先とビルド作業領域を置きます。
- `/scratch/hb15/tk7779/openfoam/gadi`には、圧縮したソース、ビルド成果物、付随記録、ケースキャッシュ、実行領域を置きます。
- `/scratch`に展開済みのビルド領域や永続ccacheを作りません。
- 玄界の成果物やキャッシュをGadiで再利用しません。

`$PBS_JOBFS`はノードごとに独立しているため、多ノード実行で共有するケースや実行記録には使いません。ビルドは1ノード内で完結するため、展開物と中間生成物を`$PBS_JOBFS`へ置けます。実行前に`/scratch`へ展開する実行環境は一時物とし、Actionsの終了処理で削除します。

GitHub Actionsの実行機は、版ごとに用意した`shared/<version>/externals`を共有します。共有物の初回作成と版の切り替えは運用者が手作業で行い、ワークフローや起動スクリプトから作成・更新しません。各実行機の`bin`、認証情報、診断記録、作業領域は共有しません。

PBSの投入先は課題`hb15`の`normalsr`です。投入、待機、終了確認、資源指定はGadi用のスクリプトに置き、PJM用の処理と共通化しません。
